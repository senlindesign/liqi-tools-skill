# 使用时 Onboarding 规范

## 目标

让用户在一次自然对话里从“我想找工具”进入“我知道为什么推荐、谁用过、还能如何继续筛选”。不要求用户学习数据库字段。

## 状态机

1. **识别**：判断用户是在按任务找工具、按 Workflow / Case 找工作方式，还是按工具看跨创作者聚合。
2. **补齐**：只询问缺失的任务、平台或关键限制；已有信息就跳过。
3. **检索**：先查 `reviewed_mentions`，再查 provisional 数据；使用同义词重复检索。
4. **解释**：最多先给 3 个候选，标注校准状态、适用场景和证据来源。
5. **收敛**：询问一个最有价值的偏好，例如预算、平台、隐私或学习成本。
6. **深入**：用户选择后，打开对应 Markdown，补充创作者原话的短摘要和访谈链接。

## 首次调用示例

用户只说“推荐几个剪辑软件”时：

> 我可以根据利器创作者的实际使用和推荐来筛选，并附上原始访谈链接。你主要在哪个平台剪辑（Mac、Windows、手机或跨平台）？有没有预算或易上手要求？

用户说“我在 Mac 上剪播客，预算不限”时，直接检索，不再重复介绍 Skill。

## 输出验收

- 每个候选都有工具名、适用场景、创作者、原始链接和短证据。
- 明确区分 `已人工校准` 与 `机器初筛`。
- 不把历史访谈当成当前价格、版本、隐私或安全结论。
- 结果超过 3 个时，先给前三个，再询问是否展开。
